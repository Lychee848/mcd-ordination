# 底图是什么，以及"每个人是不是都不一样"

> 这份文档只回答两个问题：**画面窗里那张画是怎么来的**，以及**它到底有多独特**。
> 不想读长文的结论在最后一节。

---

## 1. 底图只占一层

一张卡由三层叠出来，底图只是最里面那层：

```
┌─────────────────────────────┐
│ 卡框 / 卡名 / 星级 / 属性盘    │ ← 代码画（永远清晰、永远可复算）
│ ┌─────────────────────────┐ │
│ │  底图（plate）           │ │ ← 这张位图，就是本文的主角
│ │  画面窗里那一张画         │ │
│ └─────────────────────────┘ │
│ 种属行 / 效果框 / 攻守 / 编号  │ ← 代码画
└─────────────────────────────┘
```

**为什么文字不让 AI 画**：扩散模型画汉字会糊、会缺笔画、会漂移。一旦卡名糊了，
"这张卡是我的"这件事就不成立。所以 AI 只负责**画面**，其余全部由代码排版。

---

## 2. 三级来源，按优先级

| 优先级 | 来源 | 存在哪 | 成本 | 独特度 |
|---|---|---|---|---|
| ① | **独版**：这个用户自己的一张 | `assets/plates/users/<uid>_<role>.png` | 5–10 积分/张 | 全站唯一 |
| ② | **共享**：按画派 + 卡种 | `assets/plates/plate_<画派>_<卡种>.png` | 0（一次性制作） | 同画派的人共用 |
| ③ | **程序化**：没有素材也能出卡 | 运行时画（`plates.procedural_plate`） | 0 | 由用户种子决定几何 |

查找顺序（`plates.resolve`）：

```
users/<uid>_<role>.png
  → plate_<art>_<role>.png
      → plate_<art>_still.png   （食物卡 / 行为卡共用静物）
          → plate_<art>.png     （该画派的通用底图）
              → 程序化底图
```

`role` 是 `effect / item / spell / field`（人物 / 食物 / 行为 / 地点），**不是版式名**。
命名成 `_rite` 是不会被命中的——这个坑踩过一次。

---

## 3. 共享底图上的"构图变体"

共享底图意味着同画派的人拿到同一张画。为了拉开观感，`plates.vary()` 会按用户做一次
**确定性**的构图变换：

- 缩放 1.00–1.12
- 裁切中心偏移 ±25%
- 50% 概率水平镜像

同一用户永远同一版（刷新不换脸），不同用户不同版。**零成本、不调用任何模型。**

但要说清楚：**它改的是构图，不是内容。** 换个人看到的是同一幅画的不同裁切，
不是另一幅画。

---

## 4. 那"每个人都不一样"到底满足了吗

**不完全。** 这是设计取舍，不是 bug。

7 个画派按权重分配（18/17/15/13/13/12/12）。1000 个用户时：

| 画派 | 用户数 | 该画派人物卡底图 | 共用同一张画的人 |
|---|---:|---|---:|
| 彩色玻璃窗 | ~180 | `plate_stained.png` | ~180 |
| 湿壁画 | ~170 | `plate_fresco.png` | ~170 |
| 珐琅招牌画 | ~150 | `plate_enamel.png` | ~150 |
| 其余四派 | 各 120–150 | 各 1 张 | 各 120–150 |

所以在"画面"这一层，现在是**几百人一张画**（只是裁切不同）。
文字、星级、框色、编号、暗号是每人不同的——但**画不是**。

这满足"我这张卡和你的不一样"，**不满足"我这张画和你的不一样"**。

---

## 5. 三条路径，按成本选

| 方案 | 每人成本 | 首屏延迟 | 独特度 | 适用 |
|---|---:|---:|---|---|
| 共享 + 构图变体 | 0 | 0 | 同画派同画 | 默认、离线、评审 clone 即跑 |
| **稀有卡独版** | ~0.2 张/人 | 3–8s（仅稀有） | 稀有卡全球唯一 | **推荐：把"独版"做成稀有度的一部分** |
| 全量独版 | 1 张/人 | 3–8s（首次） | 每人一幅 | 有预算时的最终形态 |

第二条已经在代码里：`_ensure_unique_plate()` 只对 `anim >= 1`（面闪及以上）的卡调用，
且必须先配置出图后端。理由很直接——**独版是奖励，不该是默认**：
默认就独版会让每张卡都等 3–8 秒，而"稀有"也就没意义了。

1000 个用户按当前抽卡概率，约 20% 抽到面闪及以上 → 约 200 张独版图 → 1000–2000 积分。

## 6. 接自己的出图后端

不需要改代码，只设一个环境变量：

```bash
export MCD_PLATE_CMD='your-image-cli --prompt "{prompt}" --out "{out}"'
python -m mcd_ordination demo --engine png
```

`{prompt}` 由 `styles.style_prompt_block()`（画法/光/调色）+ 卡种主体描述拼成，
`{out}` 是目标路径。命令返回 0 且文件存在即视为成功。

也可以直接放文件，不接任何 CLI：

```
assets/plates/users/u_00029_effect.png
assets/plates/users/u_00029_item.png
```

放了就优先用，无需配置。

---

## 7. 三条硬约束（做底图时）

1. **绝对不要有文字。** 模型画出来的"字"会变成乱码，而卡面已经有代码画的字。
2. **不要自己画外框。** 画面窗的边框由渲染器加（三层硬边），底图带框会出双层框。
3. **正方形 1024 起步。** 画面窗会按比例 cover 裁切，非方形图会被切掉主体。
   生成图右下角常有水印，制作时裁掉底部约 9%。

---

## 8. 结论

- 底图 = 画面窗里那张位图，**只占卡面的一层**；文字/数值/编号永远是代码画的。
- 现在默认是**共享底图 + 每人不同的构图变体**，不是每人一幅画。
- 想要"每人一幅"，要么走**稀有卡独版**（推荐，成本与稀有度绑定），
  要么配 `MCD_PLATE_CMD` 做全量独版（1 张/人）。
- 零素材、零 Key、零网络时，仍然有**程序化底图**兜底，卡面不会开天窗。
