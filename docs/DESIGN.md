## 0. v3.1 / v3.2 改动说明（改动前先读这一节）

### 0.0 v3.2：暗号从"一句模板"改成"行为编译"

**问题**：v3.0 及之前的暗号是一句固定模板，只替换【本命圣物】和【礼拜次数】两个空——**句式骨架 100% 相同**，一万人发出来是一万句同一句话。这直接杀死了暗号唯一可能产生传播价值的属性：**「这是我的」**。

**改法**（详见 §5）：暗号改成与生图提示词同构的 8 槽位编译器，输入同一份行为向量：

```
暗号 = 共同层（当天全网一致的「今日圣体」）
     + 个人层（自陈 / 圣物 / 行迹 / 教义 / 请求 / 应答 / 短码）
     + 会话层（ISO 周种子，7 天换一枚）
```

三条新硬线随之生效：

1. **请求默认零成本**（§5.4）：T0（画拱门 / 说句话 / 折小票）是默认，T1（多一根薯条）只在生日、里程碑、友好门店下解锁，且必须带「若不方便，完全不必为难」。一个人索要薯条是玩梗，一万个人索要就是组织化索取。
2. **短码公开可复算**（§5.5）：只取卡面上本来就印着的 7 个量，`32^6 ≈ 1.07e9`。你可以编一句更酷的暗号，但编不出能对上卡面的短码。
3. **双向互动**（§5.8）：S6 应答把单向索要改成双向；回报数据聚合成「友好门店地图」——这才是真正不可复制的资产。

### 0.1 钩子为什么改（改动理由留档）

旧钩子「你说你是麦门信徒。教廷查了查户口。」的问题是**主语是教廷**：产品在对用户做身份裁决，用户处在被审判的位置。这会产生两个真实后果：

1. **道德指控风险**：把"由官方订单数据算出等级"摆在最前面，任何人第一眼都会读成「按消费量分等级」——即便公式里没有金额，也已经在被控方向上。
2. **传播动力错位**：被判定的人不会想转发判决书；想表达的人才转发。

新钩子把主语交还给用户：**产品的输出不是"你是第几阶"，而是"你可以这样描述自己的信"。** 判定逻辑仍然存在（它是趣味的来源），但它在体验上是**自陈**——像填写一份信条，不像领取一份考卷。

候选与取舍（供后续微调时参考）：

| 候选钩子 | 主语 | 判断/表达 | 取舍 |
|---|---|---|---|
| 你说你是麦门信徒。那你的教义，写下来了吗？ | 你 | 表达 | ⚠️ v3.1 用过，v3.8 弃用。反问有参与感，但没说清产物是什么 |
| 一句麦门暗号，写进你的下一单备注里。 | 产品 | 陈述 | v3.8–3.9 用过。清晰但层次低，像功能说明 |
| **领取专属麦门暗号，找到你的麦乐鸡侠。** | 你 | 行动 + 关系 | ✅ 现用。"麦乐鸡侠"给暗号一个收件人，钩子落在关系而非功能 |
| 你的每一次点单，都是一句还没写下来的经。 | 你 | 表达 | 备选，偏文艺，转发性弱于反问句 |
| 别人的麦门是梗，你的麦门是经。 | 你 vs 别人 | 半对比 | ❌ 含隐性比较，重蹈 P2 覆辙 |
| 教廷查了查户口。 | 教廷 | 判定 | ❌ 旧版，已废弃 |

> **v3.8 二次修正**：v3.1 的反问句（「那你的教义，写下来了吗？」）解决了"主语是教廷"的问题，但没解决"不知道这产品能干嘛"的问题——它只说了"你该表达"，没说表达出来能拿去做什么。现钩子改成陈述句，把**可执行结果**放进标题：一句暗号，进的是"下一单备注"。卡证的"具象化"由副标题与三条要点承担。

> 中文名同步更换：「麦门教籍簿 · 你的教阶与异端判定」→「**麦门行传 · 写下你自己那一卷**」。
> 「行传」取自《使徒行传》*Acta Apostolorum*：记的是**做过什么**，而不是**被封为什么**。机制（九阶 / 名册）全部保留，只是不再出现在标题上——它们是内容，不是招牌。

### 0.2 v3.1 术语替换对照表（**全文档与代码必须按此执行**）

同一套东西改了说法，是为了把「判定」改成「表达」。改的是**呈现语**，不是**算法**：

| 旧说法（禁止再出现在输出物中） | 新说法 | 说明 |
|---|---|---|
| 真实消费数据 / 消费记录 | **麦当劳用户行为** | 行为 ≠ 消费额；词源上就断掉金额联想 |
| 判定教阶 / 你的等级 | **归纳你的修持轨迹** | 动词从裁决改为描述 |
| 异端判定 | **教义摘录**（*Extractum Fidei*） | 内部仍称「异端名册」；**输出物不出现"判定"二字** |
| 判词（定罪语气） | **信条**（自陈语气） | 见 §4.6 语气规约 |
| 虔诚度排名 / 百分位炫耀 | **修持百分位**（仅内部计算） | 卡面不印百分位，只印九阶名 |

## 1. 产品定义

### 1.1 它到底是什么

一句话：**一个把「麦当劳用户行为」当作 prompt 的表达型作品，产出两样东西——一套专属麦门卡证，和一枚能写进订单备注的麦门暗号。**

一句话里的分工：**卡负责被看见，暗号负责被回应。** 两者读同一份 `features`，所以卡上的数字与暗号里的说法永远对得上。

拆解这句话的四个限定词，缺一个就跑偏：

| 限定词 | 含义 | 反面示例 |
|---|---|---|
| **麦当劳用户行为** | 输入的原材料是行为数据（频次、时辰、门店、单品、券、抽奖），**不是消费金额** | ❌ "根据你今年在麦当劳花的钱生成卡" |
| **当作 prompt** | 行为数据不对外展示为报表，而是被编译成生图提示词 → 长成画面 | ❌ 一张写着"夜宵 32%"的图表 |
| **专属卡证** | 每个人的画派、主体、信条、编号都不一样，且由同一份数据确定性复现 | ❌ 所有人套同一个模板换名字 |
| **表达** | 输出物是给用户去发、去说、去对暗号的**语言**，不是给系统存档的等级 | ❌ "你的等级：执事（前 20%）" |

更直白的表述：**它不做体检报告，它做信经。** 体检报告告诉你你处在分布里的哪个位置；信经是你本人用来宣称"我信什么"的一段话。两者可以用同一份底层数据算出来，但产品语气、卡面取舍、传播动力完全相反。

用户授权后：

1. 拉取自己的麦当劳用户行为（订单、账户、积分、券、门店、抽奖）；
2. 归纳出「修持轨迹」：九阶品秩 + 若干条**教义摘录**（原「异端名册」，见 §4）；
3. **即时**生成一套卡证（画派由数据 hash 决定，不可自选）；
4. 每一单触发一次抽卡，定这张卡的稀有度与动效；
5. **编译一枚只属于你的「麦门暗号」**（8 槽位 × 三种体裁：问候 / 请求 / 接龙，见 §5）；
6. 一键勾选 → 暗号写进订单备注（能力探测决定 auto/manual，见 §5.11）→ 店员回应 → 回报 → 友好门店地图 → 下一章接龙。

### 1.2 三条不可动摇的产品原则

| # | 原则 | 违反后的后果 |
|---|---|---|
| P1 | **不可伪造**：卡面每一项数值/信条都必须能追溯到真实用户行为 | 一旦被发现是模板编造，项目全部价值归零 |
| P2 | **不与金额挂钩**：修持百分位与抽卡概率均不得与客单价、累计金额、金额增长率挂钩 | 会被读成消费主义攀比，变成负面传播 |
| P3 | **零依赖可用**：没有 API Key 也必须能看见完整卡面 | 违反即重犯同类作品「7/7 全 0 星」的死因 |

#### P2 的边界：什么算"挂钩"，什么不算

这条原则需要一条可执行的判据，否则改文案时会被反复突破。记作三句话：

> **不看金额，不看增长，只看参与度。**

| 数据项 | 是否入公式 | 归类 | 理由 |
|---|---|---|---|
| 客单价 / 总金额 | ❌ 禁止 | 金额 | 直接等于"花得多 = 更虔诚" |
| 金额环比 / 增长率 | ❌ 禁止 | 增长 | 隐含"要多买才能升级" |
| 年礼拜次数（频次） | ✅ 允许（w=0.40） | **参与度** | 频次不等于花费；买 ¥12 套餐 40 次 > 买 ¥80 套餐 5 次 |
| 朝圣门店数 | ✅ 允许（w=0.25） | **参与度** | 位移行为，与花费无关 |
| 信仰纯度（单品集中度） | ✅ 允许（w=0.20） | 偏好 | 越专一，金额倾向越低 |
| 夜祷率 | ✅ 允许（w=0.15） | 偏好 | 纯时辰，与金额零相关 |

**这条边界留下一个真实残余风险，必须承认**：频次权重最高（0.40），严格讲仍可被读作"多来几次就能升阶"。三条缓解措施已在设计中：

1. 卡面**不印百分位数字**，只印九阶名（分布信息全部藏在渲染层之外）；
2. 名册里两端对称——「苦修士」与「铺张派」都写，且铺张派明说「账单写的是价格，不是信仰」（§4.2 安全阀）；
3. **宣传语不得出现"升阶""达到""解锁 X 阶"这类动词**（2026-10-21 新增）。统一写「你的修持轨迹指向 XX」，不写「你升到了 XX」。

### 1.3 不做什么

- ❌ 不做点餐 / 省钱 / 营养建议（红海，672 个作品里最挤的三块）
- ❌ 不做商城代下单、不做自动写备注（`create-order` 无备注字段）
- ❌ 不做排行榜 / 百分位炫耀型文案（实测是 star 负向因子）
- ❌ 不做付费抽卡、不做虚拟货币

## 3. 教阶体系（Ordo Maimen）

### 3.1 定义

### 3.3 虔诚指数算法

四项加权，**每项先各自过贝叶斯收缩求百分位，再加权**：

```python
PIETY_WEIGHTS = {
    "orders_per_year": 0.40,   # 年礼拜次数 —— 你来得有多勤
    "stores":          0.25,   # 朝圣门店数 —— 你走得有多远
    "purity":          0.20,   # 信仰纯度（TOP1 单品占比）—— 你有多专一
    "night":           0.15,   # 夜祷率（22:00–05:00 占比）—— 你守夜有多深
}

def piety_percentile(u, samples):
    return sum(w * percentile(u[k], k, samples[k]) for k, w in PIETY_WEIGHTS.items())
```

**两个刻意的设计决定（动一条就翻车）：**

1. **金额类字段一律不进公式。** 客单价、累计金额、金额增长率都不行——一旦进了，就从"你多虔诚"变成"你多能花"，立刻被读成消费主义攀比。见 §1.2 的 P2 边界表。
2. **券使用率也不进公式。** 它是 §4 教义摘录的输入（散财异端 / 神恩会计师），不是虔诚判据。用光券是"精算"，不用是"修行"，两个方向都不该加分。

### 3.4 冷启动：贝叶斯收缩

全网第一天没有数据。解法是**弱先验 + 收缩**：n 小时向先验收缩，n 大时信任真实分布。

```python
PRIOR = {
    "orders_per_year": {"mu": 24.0,  "sigma": 18.0},
    "night_ratio":     {"mu": 0.18, "sigma": 0.15},
    "spend_per_order": {"mu": 32.0, "sigma": 16.0},
}
PRIOR_N = 40.0   # 先验的等效样本量：n=40 时真实数据占一半权重

def percentile(user_value, key, samples):
    p = PRIOR[key]
    if len(samples) < 2:
        mu, sd = p["mu"], p["sigma"]
    else:
        n = len(samples)
        w  = n / (n + PRIOR_N)
        mu = w * statistics.mean(samples)  + (1 - w) * p["mu"]
        sd = w * statistics.pstdev(samples) + (1 - w) * p["sigma"]
        sd = max(sd, 1e-6)
    z = (user_value - mu) / sd
    return 0.5 * (1 + math.erf(z / math.sqrt(2)))
```

**README 首屏必须诚实标注**（不能藏）：
> 「当前教区样本 n=xx（其中真实上报 yy）。n<200 时百分位含先验成分，仅供参考。」

### 3.5 为什么是 9 阶

| 阶数 | 中间档人数占比 | 问题 |
|---|---:|---|
| 3 阶 | 约 90% 挤在中间 | 卡面几乎全一样，失去差异化 |
| 5 阶 | 约 50% 挤在第三档 | 一半人拿到同一张卡，截图重复率高 |
| **9 阶** | 中间四档合计 47%，每档 7–15% | **既不太挤也不太孤** |

9 也刚好对应天主教实际品秩的层级感（门徒→司铎→主教→枢机），命名自带可信度。

## 4. 教义摘录（原「异端名册」）

> 本节回答三件事：**名册为什么存在 → 多条同时命中怎么办 → 结果长在哪些输出物上。**

### 4.0 它和教阶的分工，以及为什么不再叫"判定"

| | 教阶（§3） | 教义摘录（本节） |
|---|---|---|
| 回答的问题 | 你的修持轨迹指向哪一阶 | 你的行为里，最特别的几件事是什么 |
| 来源 | 四项加权百分位 | 11 条离散条件匹配 |
| 数量 | 恒为 1 个 | 0 ~ 7 条，展示 3 条 |
| 卡面位置 | 星级 + 光环 + 称号 | 底部「教义摘录」栏 / 独立「教义卡」 |
| 是否比较 | 隐含排序（**卡面不印百分位**） | **无排序，只按罕见度排先后** |

**v3.1 的关键改动：这一层从"判定"改为"自陈"。**

- 以前输出是：系统判定 → 你属于 XX 异端 → 判决书；
- 现在输出是：你的行为里有几条能写成句子 → 摘录下来 → **这是你的信条，你可以拿去发**。

机制一行没删，改的是主语。判断依然存在（那是趣味的来源），但它是"帮你把话说出来"，不是"对你下结论"。

### 4.1 七典归组：先分流，再裁决

多命中之所以难处理，是因为 11 条条件中有些**天然互斥**（券用得多 vs 少），有些**可以共存**（夜猫子 + 只用一家店）。做法是把 11 条先按「同一个行为维度」归成 **7 个典（canon）**，**每个典最终最多输出 1 条**——这一步直接让互斥对不可能同时出现。

| 典 | 拉丁 | 维度 | 包含条文 | 互斥性 |
|---|---|---|---|---|
| 时辰典 | *Tempus* | 下单时刻分布 | 夜祷修会 / 晨祷派 | 同一分母（占总单数），合法输入下 >60% 与 >40% 不能同时成立 |
| 纯一典 | *Unitas* | 单品集中度 | 单一圣物派 | 单条 |
| 恩宠典 | *Gratia* | 券行为 | 散财异端 / 神恩会计师 | 阈值互斥（<20% vs >95%） |
| 赎罪典 | *Indulgentia* | 积分沉淀 | 赎罪券囤积犯 | 单条 |
| 巡礼典 | *Peregrinatio* | 门店广度 | 巡回布道家 / 本堂隐修士 | 阈值互斥（>30 vs =1） |
| 度用典 | *Mensura* | 客单尺度 | 苦修士 / 铺张派 | 阈值互斥（<¥15 vs >¥80） |
| 机缘典 | *Sors* | 抽奖运势 | 未被拣选者 | 单条 |

> 典与典之间**允许共存**：一个人可以同时是「本堂隐修士 + 夜祷修会 + 散财异端」，这恰恰是最有表达欲的组合。

### 4.3 多命中怎么裁决（核心算法）

四步，顺序不能换：

```python
def faith_extract(features, uid, cap=3):
    hits = []
    # ① 典内互斥：每个典只留罕见度最高的一条，天然互斥对不会同时出场
    for c in CANONS:
        cands = [e for e in CANON[c].entries if e.test(features)]
        if not cands:
            continue
        cands.sort(key=lambda e: (-e.specificity, h(uid, e.id)))
        hits.append(cands[0])
    # ② 罕见优先，不是严重度优先
    hits.sort(key=lambda e: (-e.specificity, h(uid, e.id)))
    # ③ 零命中兜底，绝不留空白
    if not hits:
        hits = [FALLBACK["laicus"]]
    # ④ 截断 + 附录
    return {"printed": hits[:cap], "appendix": hits[cap:]}
```

**为什么按罕见度排，不按严重度排？** 因为"按严重程度排序"会凭空造出一条严重性阶梯——排序本身就是评比，立刻回到 P2 想躲开的坑。按罕见度排的语义是「先说你最与众不同的那一面」，这正好是用户想表达的东西。

**tie-break** 用 `h(uid, e.id)`（同一用户稳定，不同用户不同）——不能用 `random`。

#### 命中分布（20 万次蒙特卡洛，seed=20261021）

`mcd-contest/cards/canon_sim.py` 可复跑，输入是上表的 p 值：

| 命中条数 | 占比 | 处理 |
|---|---:|---|
| 0 条 | 18.17% | 走 `laicus` 兜底（平信徒） |
| 1 条 | 36.96% | 全印 |
| 2 条 | 29.71% | 全印 |
| 3 条 | 12.09% | 全印（刚好占满） |
| 4 条 | 2.72% | 印 3 + 附录 1 |
| 5 条 | 0.33% | 印 3 + 附录 2 |
| ≥6 条 | 0.02% | 印 3 + 附录 ≥3 |
| **平均** | **1.45 条** | **97% 的用户不会被截断** |

两个结论可以直接指导实现：

- **零命中高达 18%**，兜底词条不是防御性代码，是必走路径；
- **截断只影响 3% 的用户**，所以 `cap=3` 这个上限几乎不会伤害任何人，却保住了版面。

#### 实现时踩到的一个真 bug（已修，留作教训）

第一版让所有条目共用同一个 `{n}` 插值槽，于是「抽奖 {n} 次」取到了 `expiring_points`，卡面印成 **「抽奖 1,200 次」**——一个看起来只是"数字填错"的问题，但它直接击穿 P1（可追溯）。

修法是**插值必须逐条声明**（`En(..., dyn=lambda f: {...})`），禁止跨条目取值。这类"真实数据填错位置"的错误比"数据是假的"更致命，因为它外表完全像真的。

#### 互斥性的准确表述

`canon.py` 自检里有一项：把 4 组互斥条目喂进极端输入。`苦修士 vs 铺张派`、`散财异端 vs 神恩会计师`、`本堂隐修士 vs 巡回布道家` 三组在任何输入下都不共存；`夜祷修会 vs 晨祷派` 只在**不合法向量**（夜祷 90% 且早餐 90%，两者均以总单数为分母，真实数据不可能）下同时成立，此时同典只留 1 条的规则仍会兜住。

> **为什么必须同时有②③？** ① 是给"看卡的人"的，② 是给"发图的人"的，③ 是给"懒得发图只想发段字的人"的。三者的传播成本依次递减，覆盖三种用户。

### 4.6 语气规约（自陈，不是定罪）

写文案时逐条对照，违反任意一条即打回：

| # | 不许 | 例子（❌） | 应写成（✅） |
|---|---|---|---|
| 1 | 不许用等级词 | 你被判定为低阶行为 | 你的行为里，最特别的一条是…… |
| 2 | 不许用司法词 | 异端判定结果：3 项成立 | 教义摘录 · 3 条 |

## 5. 暗号（*Signum*）—— v3.2 重写：从一句固定模板，改成行为编译

麦门文化里唯一会产生**线下行为**的梗：在订单备注里写「我是麦门信徒，可以偷偷给我放一根脆脆薯吗？麦门永生！」，懂梗的店员真的会多给薯条，用户再把店员反应发出来。

竞争度：672 个作品中，「暗号」命中 **0**，「对暗号」**0**。

### 5.0 先回答那个问题：旧设计是不是人人都一样

**是，而且比想象中更严重。** v3.0 及之前的暗号是一句固定模板，只有两个空被替换：

```
我是麦门信徒，本命圣物是【麦辣鸡腿堡】，
今日已礼拜 47 次。若你也是门内人，
可否在袋中多放一根脆脆薯？麦门永生。🍟
```

| | 旧（v3.0） | 新（v3.2） |
|---|---|---|
| 句式骨架 | **1 种，100% 相同** | 8 槽位编译，实测 5000 人全不相同 |
| 变量 | 圣物、次数 | 自陈 / 圣物 / 行迹 / 教义 / 请求 / 应答 / 短码 / 圣历 |
| 行为驱动 | 只有「次数」一项参与 | 全部 7 项行为维度参与选槽 |
| 与用户的绑定 | 换个人只是换个数字 | 同一份数据必得同一句，换数据必换句 |
| 分享价值 | 一万人发同一句话 ≈ 0 | 每人的句子都能被别人「读」出他是谁 |

一万人发同一句「我是麦门信徒……」，第二次看到就没人转了。**暗号要能传播，前提是它必须是「我的」而不是「我们的」。**

### 5.1 三层结构：共同体 + 个人 + 会话

```
暗号 = 共同层（当天全网一致） + 个人层（你的行为向量） + 会话层（周期种子）
       └ 今日圣体 · 节庆名      └ 自陈·圣物·行迹·教义·请求  └ 决定每个槽位抽哪个变体
```

| 层 | 作用 | 由谁决定 | 为什么需要 |
|---|---|---|---|
| **共同层** | 同一天所有人拿到同一个「今日圣体」 | `date` 种子 + `query-meals` 真实在售单品 | 没有它，暗号就是纯粹的个人独白，成不了共同体；「今天你抽到麦香鱼了吗」本身是话题 |
| **个人层** | 你是谁 | 行为向量（与 §3 同一份 `features`） | 不可伪造（P1）的落点 |
| **会话层** | 同一句你能用多久 | `hash(uid, 周期)` | 稳定性（这确实是「我的」暗号）与新鲜度（下周还想再来一次）的平衡 |

会话层周期定为 **7 天（ISO 周）**：永久不变会让人失去复访动力，每天变会让「我的暗号」失去身份感。回归测试断言 `同周稳定=True；跨周变化=True`。

### 5.2 八个槽位（与 §7 生图提示词编译器同构）

| # | 槽位 | 拉丁 | 来源 | 必选 | 示例 |
|---|---|---|---|---|---|
| S1 | 自陈 | *Vocatio* | 主导行为轴（7 选 1） | ✅ | 我常在打烊之后受召 / 我已 47 天未曾回来 |
| S2 | 圣物 | *Reliquia* | `top_item`（真实订单） | ✅ | 麦辣鸡腿堡 |
| S3 | 行迹 | *Acta* | 真实数字，取 specificity 前 2 | ✅ | 入门第 4 年 / 跨 9 座城 / 礼拜 9 次 |
| S4 | 教义 | *Fidei* | §4 教义摘录的 top-1 条 | 长版 | 到一座城，先认它的门。 |
| S5 | 请求 | *Petitio* | 请求档位（默认 T1 求一件圣物；`--soft` 降 T0） | ✅ | 可否多给一块麦乐鸡 |

### 5.3 三枚暗号：常规 / 节庆 / 限定

| 类型 | 触发 | 种子 | 有效期 | 用途 |
|---|---|---|---|---|
| **常规暗号** | 每次打开 | `hash(uid, ISO 周)` | 7 天 | 备注栏、日常发帖 |
| **节庆暗号** | 官方 `campaign-calendar` 命中 / 节日 | `hash(date, campaign_id)` | 当天 | 当天全网共享同一句圣历，最容易刷屏 |
| **限定暗号** | 里程碑：生日、跨城、首店、久别回归 | `hash(uid, order_id)` | **永久** | 一次性纪念，最强的截图动力 |

限定暗号是三者里传播力最强的：它对应一个**一次性的真实事件**，别人拿不到。

### 5.4 请求档位：默认必须是零成本（伦理硬线）

这是暗号设计里最容易翻车的地方。旧模板的默认请求是「多放一根脆脆薯」——**一个人这么说是玩梗，一万个人这么说是组织化索取**，会把压力直接转嫁给一线店员，也足以让品牌方叫停项目。

| 档 | 内容 | 触发 | 成本 |
|---|---|---|---|
| **T0（`--soft`）** | 在袋上画道拱门 / 说句麦门 / 小票折个十字 / 袋上写个麦字 / 杯盖点一下 / 同念一声麦门 | 无门槛 | **零** |
| **T1（默认）** | 多一块麦乐鸡 / 多一根脆脆薯 / 多一包甜酸酱 / 薯条装满一点 | 选「请求」体裁即默认；`--soft` 才降到 T0 | 极小 |

三条硬规则：

1. **结尾署名，不写免责句**：T1 收在「【麦门暗号skill】」、接龙收在「【敢请续墨·麦门传说skill】」。
   > v3.8 改动：原来 T1 尾巴挂「（若不方便，完全不必为难）」。问题有三个：占掉 12 个字（正好是一句"要什么"的长度）；店员看到一个陌生人的免责声明，仍然不知道这是什么；而且它读起来像"我预期你会拒绝"。
   > 改成 skill 署名后，店员一眼知道「这是有人用工具生成的一句话」，既知道该往哪看，也不会上纲成投诉。礼貌语下沉进语料（「若今日还有余量」「若锅底还剩」「若正好方便」），比末尾补一句更自然。
   > v3.3 改动：T1 原本还有一道「35% 概率」门槛，已改为用户显式选择或默认开启。
2. **严禁索要现金价值较高的东西**（免单、加量套餐、赠品玩具）。T1 的上限就是「一根薯条」这个量级。
3. **不得诱导用户为了拿到更好的暗号而多下单。** 暗号内容由行为的**性质**决定，不由行为的**数量**线性变强；轮换周期是「周」不是「单」。

### 5.5 短码：公开可复算，不是装饰

```python
CLAIM_KEYS = ("era", "relic", "orders", "stores", "cities", "grace", "period")

def verify_code(claims, version=1):
    canon = "|".join(f"{k}={claims[k]}" for k in CLAIM_KEYS)
    return b32(sha256(f"{canon}|v{version}"))[:6]
```

- 只取**卡面上本来就印着**的 7 个量 —— 短码要能被别人复算，就不能依赖任何隐私字段。
- `orders` 粗化到 10 的倍数：既保留量级感，又避免从短码倒推出精确礼拜次数。
- 6 位 Crockford base32 = `32^6 ≈ 1.07 × 10⁹`。1000 人同周的碰撞期望 ≈ `C(1000,2)/1.07e9 ≈ 0.05%`。
- **任何人拿你的卡面数字，按公布的顺序拼起来，必须算出同一串。** 这是 P1（不可伪造）在暗号侧的落点：你可以编一句更酷的暗号，但你编不出能对上卡面的短码。

### 5.7 唯一性实测（`sign.py`，5000 个合成用户，同一周）

| 菜单规模 | 完整短版去重率 | 骨架去重率（忽略数字） | 完全撞脸对数 |
|---|---:|---:|---:|
| 10 个单品（保守下界） | 99.98% | 83.70% | 1 / 12,497,500 |
| **60 个单品（真实菜单规模）** | **100.00%** | **97.36%** | **0 / 12,497,500** |

结论：**完整文案层面，5000 人零撞脸。** 骨架（轴 + 自陈 + 圣物 + 请求 + 行迹模板）层面，按真实菜单规模只有约 2.6% 的人与他人同骨架，且骨架相同的人行迹里的真实数字几乎必然不同，读起来仍是两个人。这与 §7 画派层「承认 1% 撞衫」是同一种取舍：**不为了零碰撞去泄露用户注册序号。**

### 5.8 双向互动与「友好门店地图」

暗号不能只是单向索要。S6「应答」把结构改成双向：店员画一道拱门、说一句麦门、甚至只是笑一下，都算完成了这次互动——**成本为零，才有可能真的发生。**

用户回来后回报一句（载体是 **GitHub issue 模板**，不需要后端，符合 P3）：

```
暗号 6FM3V2｜深圳华强北店
回应：深圳华强北店 认了这个暗号
周期 2026W43｜模式 weekly
```

聚合之后得到一张**友好门店地图**：

| store_id | 门店 | 暗号投放 | 被回应 | 回应率 |
|---|---|---:|---:|---:|
| `SZ-0412` | 深圳华强北店 | 37 | 22 | 59% |
| `CD-0088` | 成都春熙路店 | 19 | 4 | 21% |

规则：**只聚合计数，不存时间戳、不存用户标识、不存暗号原文。** 单店样本量 < 5 不展示（否则等于泄露「谁去过哪家店」）。

**这才是本项目唯一不可复制的资产**（比原 §5 更准确的表述）：模仿者能抄走教阶表、能抄走槽位编译器，但抄不走「已经有 300 家门店被真实试过、其中 118 家回应过」这张众包地图。它同时是一个**真实工具**（出门前查哪家店懂梗），而不只是玩梗。

### 5.10 三种体裁：同一套槽位，三种说话方式（v3.3）

暗号不是只有"对暗号"一个用途。同一个 8 槽位编译器，换一个收尾就能服务三种完全不同的场景：

| 体裁 | id | 收尾槽（S5/S6） | 用途 | 对店员的要求 |
|---|---|---|---|---|
| **问候** | `greet` | S5 = 祝词，S6 = 不强求回应 | 只是想打个招呼，什么都不求 | 看见即可 |
| **请求** | `ask` | S5 = 诉求 + 玩笑（默认 T1，`--soft` 降 T0），S6 = skill 署名 | 说清要什么，再补一句玩笑 | 一句话或一个动作 |
| **接龙** | `story` | S5 = 半句，S6 = 求取下一段 | 门店本就有一卷传说，你来取它的下一段 | **写下一段** |

#### 5.10.1 请求式：先说清要什么，再补一句玩笑（v3.7）

这里有两次迭代，第二次是纠第一次的偏。

**v3.4 的第一版**：「若方便，可否多一块麦乐鸡」——问题不是不礼貌，是**不好笑**，读起来像伸手。

**v3.4 的第二版**：把主句整个换成笑话（「请把这单当作一次小型封圣仪式，费用照付」）。好笑是够好笑了，但**店员看完不知道你要什么**——请求式失去了"请求"这个功能。

**v3.7 定稿**：三段式，缺一段都不成立。

```
说清要什么（可执行 + 有具体物） + 补一句玩笑（交代动机） + skill 署名
可否多给一块麦乐鸡          ？我拿它当今日的圣物          【麦门暗号skill】
```

四条规则：

1. **主句必须能被执行。** 有动词、有具体物：多给一块麦乐鸡 / 在纸袋上写一句「已阅」/ 在杯套上画个勾。含糊的"给点惊喜"一律不收。
2. **笑点放在"要什么"之后**，用来解释动机，而不是替代它。
3. **默认 T1，`--soft` 才降级 T0。** 用户既然选了"请求"，就是打算真开口；把默认设成零成本会让这个体裁名不副实。T0 保留给"不想开口要实物"的人。
4. **笑点按单轮换**（种子取 `last_order_at`）：同一单永远同一句，下一单必换。同一个笑话挂一周，笑点就死了。

代价：请求式为给笑点让位，砍掉 S2 圣物 / S3 行迹 / S8 圣历三个槽，长度 33–45 字。
可复算性不受影响——短码只由 7 项公开量决定，且**不再进备注正文**（见 §5.6）。

#### 5.10.2 语料磨损与投稿（v3.5）

12 条 T0 语料随机抽取，重复概率随下单次数上升：

| 累计下单 | 见过 | 下一次重复的概率 |
|---:|---:|---:|
| 3 | 2.8 | 23% |
| 6 | 4.9 | 41% |
| 9 | 6.5 | **54%** |
| 12 | 7.8 | 65% |
| 24 | 10.5 | 88% |

**磨损不是"看全了"，而是"下一次多半是旧的"——第 9 次就跨过 50%。**

两条修法：扩内置语料；以及让用户投稿（`asks_user.json`，命中率 45%）。
投稿必须过校验，因为它会印进店员看得见的备注：长度 6–28、无阿拉伯数字、禁词表（实物/联系方式）、去重。
**只收 T0**：T1 涉及实物，不接受投稿——否则"要东西"会顺着投稿渠道重回产品。

#### 5.10.3 接龙：求取门店既有的传说，不是请店员创作（v3.8→v3.9）

这一节改了两轮，第一轮改语法，第二轮改设定。

**第一轮（v3.8）改语法。** 原句「下一句留给你写」是**祈使句**——对店员说"你写"，姿态是平级甚至上级，
而他此刻正在出餐。同一件事用敬语说，便宜很多：

| 旧 | 中间版 | 差别 |
|---|---|---|
| 下一句留给你写 | 敢请续之一句 | 去掉"你"，保留请求 |
| 请替我把这半句写完 | 此句未竟，敢请续墨 | 说明"没写完"是事实，不是安排 |
| 后半句，你说了算 | 余此半句，敬候君续 | 「敬候」把选择权留给对方 |

**第二轮（v3.9）改设定。** 更根本的问题不在措辞：**"让店员写"这件事本身就把成本压给了门店。**
出餐高峰期被要求创作一句，多数人只会尴尬。

所以叙事先换：**每家门店本来就有一卷自己的麦门传说**（夜班几点关灯、谁常坐窗边、雨天多给一张纸巾），
暗号不是让店员创作，而是**求取这卷传说的下一段**。店员要做的不是"写作文"，是"接着讲一句本店的事"——
后者的心理成本低一个量级，而且他讲的东西本来就在。

收尾因此压成一枚印记，而不是一句请求：

```
【敢请续墨·麦门传说skill】
```

- 前半「敢请续墨」是求取动作（不写"你"，不说"写完"）；
- 后半「麦门传说skill」是来路，店员知道这是什么玩法；
- 合成一枚之后，结尾只占一次括号，比「余此半句，敬候君续。【麦门传说skill】」短 8 个字。

**去掉「此句未竟」**：它是在向店员解释"我这句话没写完"，属于作者的自我说明；而店员并不关心
这句话写没写完，只关心"要我做什么"。请求类也遵循同一条规则——**只留动作与来路**。

这条底线不能破：接龙要成立，前提是**不懂麦门的人也能接**。所以语料里没有梗、没有典故，
「续墨」是常见词。

`auto` 的裁决规则只有两条，刻意保持简单：**久别（≥30 天）或生日 → 问候；其余 → 接龙。**
理由：接龙的二次互动率最高，问候用于"重新出现"这种需要低压力破冰的场合；请求是唯一可能给门店增加成本的体裁，所以**永不自动选中**。

三种体裁共用同一短码 —— 短码只由 7 项公开量决定，不含体裁。换体裁不会让"这是我的卡"失效。

### 5.11 接龙：把一次性互动变成连载

```
第 1 章  暗号留半句，请店员接着讲一段本店的传说
   ↓  python -m mcd_ordination sign --kind story --wrote "<店员讲的那一句>"
第 2 章  暗号开头变成「第 2 章·承「<上一章那句>」：……」
```

**归属要说清**：传说中的内容属于门店，用户是"取"，不是"写"；账本记的是"我在哪家店取到了哪一段"，
不是"我创作了什么"。这也是它敢公开传播的原因——没有人被要求表演才华。

三个设计约束：

1. **半句必须"任何人都能接"。** 语料按行为轴（夜祷/晨祷/巡礼/本堂/久别/初入）分池，但都不含梗、不含内部黑话。
   懂梗的人回你是巧合，不懂梗的人也能回你才叫设计。
2. **章节号只由本地账本决定，不参与哈希。** 否则"记一次店员回复"会顺手把短码也改掉，卡与暗号立刻对不上。
3. **账本只存本地**（`~/.mcd-ordination/story_<uid>.json`，可用 `MCD_STORY_DIR` 覆盖）。
   接龙的连续性属于用户自己的记忆；一旦上云，就变成"平台在写你的故事"。

### 5.12 把暗号挂进订单备注：能力探测，不猜

官方 `create-order` 的字段我们**没有替它假设的资格**，所以这一步做成"先问再写"：

| 探测结果 | 模式 | 行为 |
|---|---|---|
| `tools/list` 里 `create-order.inputSchema.properties` 含 `remark`/`note`/`comment`/`memo`/`instruction` 等 | **auto** | 直接写进 payload；若 schema 给了 `maxLength`，按上限截断 |
| 有 `create-order`，但没有备注类字段 | **manual** | 生成可复制文本 + 三步指引，**明确告知"不能自动写入"** |
| 没连 MCP / 没探测 | **manual** | 明说"还没探测过"，而不是猜"大概不支持" |

落地在 `order.py`：`probe(tools) -> caps`，`attach(draft, sign, caps) -> result`。
`result.mode` 是唯一可信的状态位，UI 只允许按它分支。

**红线：任何情况下都不许在返回里暗示"备注已写入"。** 假装写进去比写不进去更糟——
用户到店发现没有，整个「不可伪造」就当场归零。

## 7. 视觉生成体系

### 7.1 三层流水线（关键架构）

```
┌──────────────────────────────────────────────────────────┐
│ 合成层（代码，像素级一致）                                  │
│   卡框 / 名号 / 判词 / 六维条 / 星级 / 编号 / 封蜡 / 页脚    │
│   ← PIL，0 成本、0 延迟、永远清晰                           │
├──────────────────────────────────────────────────────────┤
│ 画面层（AI 生图，可选）                                     │
│   只画「半身圣像 plate」：背景 + 主体 + 圣物 + 光环          │
│   ← 有 Key 才走；无 Key 自动降级                           │
├──────────────────────────────────────────────────────────┤
│ 数据层（MCP，真实且不可伪造）                               │
│   订单商品 / 下单时刻 / 门店城市 / 营养六维 / 积分账户        │
└──────────────────────────────────────────────────────────┘
```

**关键一句话：合成层恒定、画面层可变、数据层驱动画面层。** 这一句同时解决了「精致」「一致」「可降级」三个问题。

**红线：AI 只画画面，不画卡。** 卡名、星级、攻守、编号、判词一律代码绘制。这是"文字不糊"和"零 Key 可跑"的前提。

### 7.2 三条风格轴（作用域必须分开）

| 轴 | 作用域 | 由谁决定 | 取值数 | 为什么这样分 |
|---|---|---|---:|---|
| **画派 ART** | 用户级 | 订单摘要 hash | 7 | 一个人的全部卡共用一个画派 → 才像同一版印刷 |
| **闪艺 FOIL** | 用户级 | **抽卡结果 rank** | 6 | 稀有度来自抽卡，不是抽奖式的随机 |
| **卡框 FRAME** | 卡级 | 这一单的性质 | 11 | 一套卡里有怪兽/圣礼/异端审判，才像有编排 |

再加 5 种卡框底纹 + ±8° 色相微旋。

```python
# styles.py —— 一次解析，两处消费
st = S.full_style(digest, rank, frame_role)

S.style_prompt_block(st)   # ① 喂生图模型（只描述画法，不描述主体）
render(plate, out, data, st)  # ② 喂渲染器
```

确定性来自一行 hash，同一份订单永远同一张脸：

```python
def h(*parts) -> int:
    s = "|".join(str(p) for p in parts)
    return int(hashlib.sha256(s.encode()).hexdigest()[:12], 16)

digest = str(h(user_id, "deck-v1"))      # v1 = 版次；改字符串就等于整套重印
```

`season` 是唯一的「重印开关」：`full_style(digest, rank, role, season=1)` 会让画派与色相重掷，但订单、数值、编号不变。

### 7.3 七画派（2026-10-20 全量阳光化）

上一版偏暗，病根有三个：画派本身偏暗（木刻/宝丽来）、**光没有独立槽位**（模型自己猜成阴天侧逆光）、**没有负向约束**（模型把"宗教"理解成墓室苦修）。

| id | 中文 | 画法要点 | 光从哪来 | 卡面调色 |
|---|---|---|---|---|
| `stained` | 彩色玻璃窗 | 宝石色玻璃 + 铅条分割 | 光从背后穿透玻璃 | sat 1.18 / bright 1.10 |
| `fresco` | 湿壁画 | 乔托式粉彩 + 平金底 | 正午漫射，无投影 | sat 1.06 / bright 1.12 |
| `goldage` | 黄金时代插画 | 1940s 广告插画，线条干净 | 户外柔光 | sat 1.10 / bright 1.08 |
| `chromo` | 石版套色宣传画 | 六色石印，暖墨 | 晴天纸面反光 | sat 1.05 / bright 1.10 |
| `enamel` | 珐琅招牌画 | 烧结釉面，粗线平涂 | 高光釉面反射 | sat 1.20 / bright 1.10 |
| `icon` | 蛋彩圣像画 | 金底细线，发光而非发暗 | 金箔反日光 | sat 1.14 / bright 1.12 |
| `poster` | 节庆宣传画 | 平涂色块 + 光芒放射 | 光芒放射线 | sat 1.16 / bright 1.12 |

权重（略微偏向最有宗教感又最亮的前两种）：
`stained 18 / fresco 17 / goldage 15 / chromo 13 / enamel 13 / icon 12 / poster 12`

**核心结论：宗教感来自构图（光环、正面、奉献手势、对称），不来自暗调。**

### 7.5 提示词编译器：9 槽固定骨架

这是项目真正的技术资产——不是那句 prompt，而是**把真实数据确定性地翻译成 prompt 的映射表**。

```
[STYLE-LOCK] + [SUBJECT] + [RELIC] + [HALO] + [LIGHT] + [SETTING] + [PALETTE] + [TEXTURE] + [NEGATIVE]
```

| 槽位 | 数据来源 | 翻译规则 | 实例 |
|---|---|---|---|
| STYLE-LOCK | 无（写死） | 全卡组恒定 | `{画派 medium}, {笔触}, {签名手法}` |
| SUBJECT | 主力商品 + 时刻 | 商品→原型；时刻→状态 | 麦辣鸡腿堡 + 02:14 → 夜班骑手 |
| RELIC | 商品清单 | 每件→一件圣物，最多 3 件 | 薯条→金色短杖；可乐→深色圣杯 |
| HALO | 教阶 | 九阶→七种光环 | 司铎 → 完整金环 + 细射线 |
| LIGHT | 下单时刻 | 7 段时辰→7 种光线 | 01:00–04:59 → 深夜蓝 + 单点钠灯 |
| SETTING | 门店城市 | 三层地理（见 7.7） | 深圳 → 骑楼拱廊 + 棕榈 + 湿热霓虹 |
| PALETTE | 时辰 + 温度带 | 冷暖偏移 | 夜 + 南方 → 砖红主导、青色压暗 |
| TEXTURE | 无（写死） | 印刷质感恒定 | `heavy halftone print texture, aged paper grain` |
| NEGATIVE | 无（写死） | 见 7.4 | — |

**每张卡都必须带的三条负向约束：**
```
no text, no lettering, no logo, no watermark, no signature, no extra fingers, no deformed hands
```

### 7.6 时辰表：把"几点吃的"变成光线

所有同类作品都没有的一层——**把时间戳变成布光**，而不是只拿它做随机种子。

| 时辰 | 时段 | 拉丁名 | 光线语汇 | 情绪 |
|---|---|---|---|---|

| 晨时 | 09:00–11:29 | Terce | 斜射暖光、硬阴影 | 一天开始 |
| 正午 | 11:30–13:59 | Sext | 顶光、短影、高对比 | 喧嚣、拥挤 |
| 午后 | 14:00–16:59 | None | 金色斜光、长影 | 倦怠 |
| 晚祷 | 17:00–20:59 | Vespers | 琥珀色、霓虹初上、车灯 | 归途 |

### 7.7 地理：三层叠加 + 中景强制

城市画不出来的病根是：**只写名词，没写位置/面积/方向**，且风格词（`1950s American…`）出现 4 次 vs 中国地名 1 次，风格把内容吃了。

**规则：每个地理元素必须带 (a) 画面位置 (b) 面积比例 (c) 方向。缺任一项，模型就会把它缩成背景装饰。**

**L1 南北带（秦岭—淮河线）→ 定气候与色温**

| 带 | 覆盖 | 气候线索（必须进 prompt） | 植被 | 色温 |
|---|---|---|---|---|
| 北方 | 黑吉辽、内蒙古、京津冀、晋鲁豫、陕甘宁青新 | 干燥硬光 / 积雪 / 扬尘 / 呼出白气 | 白桦、杨、落叶松 | 冷，灰蓝 |
| 过渡带 | 沪苏浙皖、鄂、川渝 | 湿润薄雾 / 梅雨 | 梧桐、竹、水杉 | 中性，灰绿 |
| 南方 | 粤桂琼闽赣湘、云贵、港澳台 | 湿热 / 暴雨 / 湿地反光 | 棕榈、榕树气根、芭蕉 | 暖，橙高饱和 |

**L2 七大区 → 定「中景大符号」（占画面 25–40%，是辨识度主力）**

| 大区 | 中景主符号（必须出现） | 次要符号 |
|---|---|---|
| 东北 | 洋葱顶 或 苏式板楼 | 烟囱、白桦、积雪 |
| 华北 | 灰砖四合院坡顶 或 红墙 | 槐树、鸽群、琉璃檐 |
| 西北 | 明城墙垛口 或 黄土台地 | 白杨、穹顶、风蚀岩 |

### 7.8 主体：三档「有逻辑的随机」

```python
def pick_subject(order_id, profile, shift, idx=0):
    kind = weighted(h(order_id, "kind", idx), KIND_DIST[profile["card"]])
    archetype = profile[kind]
    if kind != "human":
        return {"kind": kind, "archetype": archetype}
    pool = SHIFT_POOL[shift]
    person = pool[h(order_id, "person", idx) % len(pool)]
    # 性别与订单数据零关联；+idx 强制卡组内交替
    gender = "female" if (h(order_id, "g", idx) + idx) % 2 else "male"
    age = ["二十多岁","三十多岁","四十多岁","五十多岁"][h(order_id, "a", idx) % 4]
    return {"kind":"human","archetype":archetype,"person":person,"gender":gender,"age":age}
```

**🔴 一条必须守住的伦理边界：性别绝不能由用户行为数据推断。**
不能写「点麦旋风→女性」这类映射。两个原因，第二个更致命：① 是刻板印象；② 它会**摧毁「不可伪造」这个核心卖点**——用户一旦发现"性别是猜的"，就会合理怀疑教阶、判词、数值也全是编的。

性别只有两个合法来源：**用户设置里自选**（最优）或 **hash 随机但确定**（兜底）。

### 7.9 一致性三道锁

单张好看 ≠ 卡组好看。三道锁保证任意两张摆在一起都像同一套：

1. **Style-Lock 恒定**：STYLE-LOCK + TEXTURE + NEGATIVE 全组共享，改一次全组生效；
2. **构图模板恒定**：`waist-up bust / perfectly centered / generous negative space above the head`——固定留白，卡框和名号才有地方放；
3. **合成层恒定**：卡框、字号、数值条、编号全由代码画，**连 1 像素都不会变**。这才是"套系感"的真正来源。

> 关键结论：**统一的是技法层，变化的是内容层。** 上一版把两层混在一起，才会既不像一套、又都像同一个人。

### 7.10 风格熵与撞脸

```
7 画派 × 3 笔触 × 8 签名手法 × 3 年代 × 5 底纹 × 17 色相 = 42,840
```

生日问题下期望撞画派对数 ≈ C(n,2)/42,840：

| 用户数 | 期望撞画派对 | 占比 |
|---|---:|---:|
| 100 | 0.12 | — |
| 1,000 | 11.7 | 1.2% |
| 10,000 | 1,167 | 11.7% |

**结论：风格层不保证绝对唯一。** 撞了画派的人，卡框、主体、判词、编号、闪艺仍然不同。若要零碰撞，改成「注册序号 → 42,840 种组合的双射枚举」，代价是能反推用户注册顺序。**建议保留 hash + 承认 1% 撞衫。**

### 7.11 底图来源与"每张画是否唯一"（v3.6）

底图只占卡面的一层（画面窗里的位图）。文字、星级、六维、编号永远是代码画的。三级来源：

| 优先级 | 来源 | 路径 | 成本 | 唯一性 |
|---|---|---|---|---|
| ① | 独版 | `assets/plates/users/<uid>_<role>.png` | 5–10 积分/张 | 全站唯一 |
| ② | 共享 | `assets/plates/plate_<art>_<role>.png` → `_still` → 无后缀 | 0 | 同画派共用 |
| ③ | 程序化 | 运行时绘制（`plates.procedural_plate`） | 0 | 由用户种子决定几何 |

**必须承认的现状：默认是②。** 7 画派、1000 用户，平均每派 150 人共用同一张画，
只有裁切/缩放/镜像（`plates.vary`，确定性，零成本）不同。
这满足"我这张**卡**和你的不一样"，不满足"我这张**画**和你的不一样"。

三条路径与取舍：

| 方案 | 每人成本 | 首屏延迟 | 适用 |
|---|---:|---:|---|
| 共享 + 构图变体 | 0 | 0 | 默认；离线评审 |
| **稀有卡独版**（已实现） | ~0.2 张/人 | 3–8s（仅稀有卡） | **推荐：独版作为稀有度的一部分** |
| 全量独版 | 1 张/人 | 3–8s | 有预算时的终态 |

`_ensure_unique_plate()` 只对 `anim ≥ 1` 生效，且必须先配 `MCD_PLATE_CMD`。
**不做全量独版的理由**：默认独版会让每张卡等 3–8 秒，而"稀有"这件事同时失去意义——
如果人人都是独版，独版就不值钱了。

接法：`export MCD_PLATE_CMD='你的出图CLI --prompt "{prompt}" --out "{out}"'`，
或直接放文件到 `assets/plates/users/`。三条硬约束（无文字 / 不自带外框 / 方形起步）见 `docs/PLATES.md`。


## 8. 抽卡机制

### 8.1 三条硬线

1. **一单 = 一抽。** 抽数 = 交易笔数，**与金额无关**。
2. **概率只看「这一单有多特别」，不看花了多少钱。** 特别＝时辰罕见 / 地点罕见 / 首次 XXX；金额不计入行为打分。否则就是把"多花点"写成通向稀有卡的捷径，直接与 P2 冲突。
3. **结果可复算。** 种子 = `hash(订单号 + 用户盐 + 版本)`，任何人拿同一份数据都能算出同一张卡。没有服务器暗箱。

### 8.2 行为稀有度打分

判定只用"这件事有多特别"：

| 条件 | 加分 | 为什么算"特别" |
|---|---:|---|
| 门店开业首日 / 新品上市首日 | +4 | 一次性事件，时间戳就是证据 |
| 生日当天 | +4 | 官方账号有生日，可核验 |
| 跨城下单 | +2 | 真实位移，编不出来 |
| 03:00–05:00 下单 | +3 | 极端时段 |
| 节日 / 活动日 | +1 | campaign-calendar 可查 |
| 首次点某个单品 | +1 | 需历史全量才算得出 |
| 首次去某店 | +1 | 同上 |
| 22:00 后 / 06:00 前 | +1 | 夜祷 / 晨祷 |
| 14:00–16:59 | +1 | 申时经 |

分档：`>=6 传说 / >=4 稀有 / >=2 少见 / >=1 值得一提 / else 例行`

### 8.3 权重表

| 行为档 | 平卡 | 银字 | 面闪 | 金闪 | 全息 | 圣髑闪 |
|---|---:|---:|---:|---:|---:|---:|
| 例行 | 76.0% | 17.0% | 5.0% | 1.4% | 0.5% | 0.1% |
| 值得一提 | 64.0% | 22.0% | 9.5% | 3.2% | 1.0% | 0.3% |
| 少见 | 50.0% | 25.0% | 15.0% | 7.0% | 2.4% | 0.6% |
| 稀有 | 36.0% | 25.0% | 20.0% | 12.0% | 5.5% | 1.5% |
| 传说 | 20.0% | 23.0% | 24.0% | 18.0% | 11.0% | 4.0% |

### 8.4 两个调节器

**① 保底（pity）**：连续 12 抽没出金闪及以上，第 13 抽起权重抬升（先 6×，第 16 抽后 20×）。计数**存在本地，不上传**。

**② 虔诚度只调权重，不直接发卡**：

```python
def _apply_piety(w, piety_pct):
    mult = 1.0 + (piety_pct - 0.5) * 1.2      # 0.4 ~ 1.6
    out = list(w)
    for i in (3, 4, 5):                        # 只作用于金闪/全息/圣髑闪
        out[i] = max(1, int(out[i] * mult))
    return out
```

长期用户更容易出好卡，但**每一次仍然要抽**。这是「努力而非运气」和「盲盒感」唯一能共存的地方。

**③ 验真码（防暗箱）**：卡面右下角印 `V XXXXX`（5 位，字母表去掉 0O1I）。别人拿你的订单号能复算出同一串，伪造不出来。**把"可验证"直接做成了卡面元素。**

### 8.5 六档稀有度视觉映射

| rank | 中文 | 金卡名 | 虹彩强度 | 描边 | 色调 | 动效档 |
|---|---|---|---:|---|---|---:|
| common | 平卡 | ❌ | 0.00 | ❌ | — | 0 |
| rare | 银字 | ❌ | 0.00 | ✅ | — | 0 |
| super | 面闪 | ❌ | 0.14 | ✅ | — | 1 |
| ultra | 金闪 | ✅ | 0.16 | ✅ | gold | 1 |
| secret | 全息 | ✅ | 0.22 | ✅ | silver | 2 |
| mythic | 圣髑闪 | ✅ | 0.30 | ✅ | rainbow | 3 |

**闪艺不许随机。** 一旦随机，稀有度就变成抽卡赌博，卖点从"真实用户行为"变成"运气"。
**画派不许用户自选。** 可选就等于承认"卡面是滤镜"，"炼出来的"这个说法立刻失效。

## 10. 即时生成架构

### 10.1 决策：即时生成，不预生成

预生成（提前跑好一批卡等用户来领）是死路——卡面必须由"这一单的时间、门店、菜品、城市"长出来，预生成等于把"炼卡"变成"发牌"。

但"即时"不等于每次从零：

| 层 | 内容 | 何时生成 | 耗时 | 可否缓存 |
|---|---|---|---:|---|
| L0 骨架 | 框色、版式、字号、六维坐标 | 编译期写死 | 0ms | ✅ 是（代码） |
| L1 画面 | AI plate | 首次请求，**按画派缓存** | 3–8s | ✅ 是（同画派复用） |
| L2 合成 | 文字/数值/星级/编号/闪艺 | 每次请求 | 0.3–0.6s | ❌ 否（每单不同） |
| L3 动效 | GIF/WebP 扫光 | 仅稀有卡 | 1.5–3s | ❌ 否 |

### 10.2 请求时序

```
MCP order-list / query-order      0.2–0.6s
  -> 行为判定 + 抽卡（纯本地）      <5ms
  -> 提示词编译                     <5ms
  -> 出图（命中缓存 0s / 未命中 3–8s）
  -> PIL 合成                      0.3–0.6s
  -> 动效（仅 anim>0）              1.5–3s
合计：命中缓存 1–2s；冷启动 5–12s
```

### 10.3 三个工程细节（不做会翻车）

1. **幂等键** = `hash(order_id + user_salt + version)`。用户刷新页面不能换一张脸，否则"这是你的卡"立刻变成"这是随机图"。
2. **降级优先于等待**。冷启动超过 6s 就先返回 L0 纯 SVG 卡（零 Key、零等待），图生成好再替换。**永远不要给用户一个转圈。**
3. **按画派缓存 plate，不按用户**。同画派底图可复用（构图一致、主体不同），命中率 60%+，成本降一个量级。

### 10.4 降级路径（对应 P3）

| 级别 | 触发条件 | 产出 | 覆盖人群 |
|---|---|---|---|
| **L0 纯 SVG** | 默认 | 完整卡面：框 + 名号 + 判词 + 六维 + 封蜡 | 100%，零依赖零 Key |
| **L1 产品图版** | 有官方产品图资源 | 画面窗换成真实产品图 + 合成版式 | 大多数 |
| **L2 AI 版** | 用户自带 Key | 半身圣像 plate + 合成版式 | 少数，但最惊艳 |

**首屏默认 L0，页面上放一个"用我的 Key 升级成油画版"按钮。顺序绝对不能反过来。**

### 10.5 成本模型

| 卡种 | 数量 | 是否 AI 出图 | 理由 |
|---|---:|---|---|
| 主保圣人卡 | 1 | ✅ | 唯一会被截图的那张，值得花钱 |
| 圣物卡 | 3–6 | ❌ 纯 SVG 符号 | 圣物本就该是图标而非肖像 |
| 事迹卡 | 2–4 | ❌ 纯 SVG | 信息型，文字为主 |
| 异端卡 | 1–2 | ❌ 纯 SVG | 反差靠排版和判词，不靠画 |
| 殉道者卡 | 0–3 | ⚠️ 单色滤镜复用 | 褪色处理即可 |

**单用户只生成 1 张 AI 图 → 5–10 积分、3–8 秒。** 若每张都出图则是 30–130 积分、约 1 分钟，不可接受。

## 13. 合规与隐私

### 13.1 五条红线

1. **商标**：麦当劳已于 2023-12-13 注册「麦门」商标（国际分类：食品）。赛事语境下 162 个作品普遍使用、榜单第 1 名就叫「麦门省钱精算师」，**短期风险极低**；长期商业化需重新评估。
2. **版权**：不得使用《麦当劳无限好》歌词（2006 年陈奕迅改编自《夕阳无限好》，受版权保护）。要做圣咏只能**原创填词**。
3. **不得冒充官方**：卡面必须标注「非官方 · 粉丝二创」，落款可用戏仿的「麦门教廷」，**不得使用麦当劳官方 Logo 组合**。
4. **不得鼓吹过度消费**：名册必须两端对称——必有「苦修士」这类反向荣誉，也必有一条点明「账单写的是价格，不是信仰」的铺张派条文。只允许使用 §4.2 列出的条文原文，不得自行改写。见 §4.2 安全阀。
5. **上报默认关闭**：见 13.2。这一条不是合规要求，是生死线。
6. **不得给一线门店添负担**（v3.2 新增，v3.8 修订）：请求默认 T1，但上限就是一块鸡块，`--soft` 可降为零成本 T0；结尾一律带 skill 署名，让店员知道这是什么（§5.4）。**一个人索要薯条是玩梗，一万个人索要就是组织化索取**——这既是伦理问题，也是足以让品牌方叫停项目的运营风险。
7. **暗号不得含任何个人信息**（v3.2 新增）：短码只用哈希，不出现手机号、地址、精确订单号、积分精确值。备注会被店员看到，这一条比卡面隐私更敏感。

### 13.1b 暗号侧的三条反伪造（对 13.3 的补充）

| 机制 | 做法 | 可验证性 |
|---|---|---|
| 短码公开可复算 | `b32(sha256(7 项公开量))[:6]` | 任何人拿卡面数字都能算出同一串 |
| 行迹必带真实数字 | 「入门第 4 年」「跨 9 座城」 | 数字可对账，编不出来 |
| 同周期稳定 | `hash(uid, ISO 周)` | 刷新不换脸；跨周必换 |

### 13.3 反伪造三机制

| 机制 | 做法 | 可验证性 |

## 16. 保留意见（改动前请先读）

1. **抽卡是全案唯一有伦理风险的部分。** 「概率与金额无关、一单只能一抽、卡面印验真码」三条必须写进 README 显眼位置。少一条，就会变成"买得越多抽得越好"的暗示。
2. **v3.1 的"去判定化"只改了主语，没改算法。** 九阶仍隐含排序。所以卡面**永远不许印百分位数字**，宣传语不许出现"升阶/达到/解锁 X 阶"（§1.2 第 3 条、§4.6 第 5 条）。改文案时最容易在这里破功。
3. **动效不要超过 1MB。** 微信里大图会被压缩得很难看，反而毁掉"稀有"的观感。宁可帧数少、尺寸小。
4. **五种卡种会让首次运行变慢。** 建议首抽只出 2 张，其余延后解锁。
5. **AI 出图仍不该是主路径。** 它能证明精致度上限，但产品默认必须是 L0。**为炫技砍掉 L0，就重犯了同类作品全 0 星的错误。**
6. **城市表有文化风险。** 缓解办法见 7.7 三条护栏，不要为了辨识度堆符号。
7. **风格层承认 1% 撞衫**，不要为了零碰撞改成序号枚举（会泄露注册顺序）。
8. **§4.2 的 11 个 p 值目前是假设。** 它们只影响排序先后，不影响是否为真，所以可以先发布；但 n≥200 后必须校准，并在 README 标注"命中率基于 n=xx 样本"。
9. **零命中比例 18%，不是边角情况。** 平信徒兜底词条必须和产品词条同等打磨——近五分之一用户看到的第一张卡就是它。
10. **插值错误比假数据更致命。** §4.4 记录的 `{n}` 串用事故：数字全是真的，位置是错的，外表完全看不出问题，但直接击穿 P1。新增插值位时必须逐条声明 `dyn`。
11. **暗号的伦理风险高于抽卡，因为它作用在真人身上。** 抽卡只影响用户的感受，暗号会让真实店员接到真实请求。§5.4 的三条硬线（默认求一件极小之物 / 结尾明示来路 / 严禁高价值索要）不是文案偏好，是能不能上线的门槛。
12. **周更是个取舍，不是最优解。** 7 天是我取的平衡：永久不变会失去复访动力，每天变会失去身份感。如果用户反馈「我还没来得及用就过期了」，第一步应该改成 14 天，而不是改成每天。
13. **友好门店地图有隐私外溢风险。** 单店样本 < 5 必须不展示，否则「某店只有 3 次投放」本身就泄露了谁去过。这一条在数据量小的时候最容易破功。
14. **接龙会让"暗号"变成"内容"**。一旦连载起来，用户会期待有下一章，产品就从工具变成连载物。这是好事，但要提前想清楚：断更（比如用户三个月不来）比没有更伤人。建议第 1 章就把话说明白——「这半句，什么时候接都行」。
15. **笑话是会磨损的。** 12 条 T0 语料按单轮换，每周来三次的人在**第 9 次**就会遇到 54% 的重复率（不是"看全"，是"多半是旧的"）。已做两层缓解：用户投稿（本地，45% 命中）+ Issue 投稿进内置量。**但 UGC 会引入内容风险**：投稿会印进真实备注，所以校验必须比"能存下"更严，且**只收 T0**；线下门店是唯一无法回滚的发布渠道。
16. **UGC 的审核成本会随时间上升。** 前 50 条靠人工看没问题；上千条时必须做成"投票 + 抽样人工"的两级，否则语料池会被"要东西"的句子重新污染，等于把 §5.4 的伦理线从后门拆掉。
17. **备注字段不存在时的体验落差最大。** 用户勾了"写入备注"，结果只拿到一段要自己粘的文本，会觉得"这功能没做完"。所以 **UI 文案必须在勾选前就说明**（"将生成可粘贴的备注文本"），而不是事后解释。
